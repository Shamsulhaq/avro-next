# Decisions
- 2026-11-10 ADR-1: Build from scratch on riti instead of reverse engineering iAvro (Intel-only, closed). Swift + InputMethodKit, riti static lib via bridging header.
- 2026-11-10 ADR-2: Rust installed via rustup (user-level) because Homebrew sandbox fails on macOS 27 (sandbox-exec not permitted).
- 2026-11-10 ADR-3: Commit on Space/Return/Tab/click; riti keeps punctuation inside its buffer.
- 2026-11-10 ADR-4: Distribute as DMG containing a component .pkg installing to /Library/Input Methods (system-wide), plus uninstaller. Settings (layout, suggestions, candidate style/size, Probhat options) stored in UserDefaults and applied live via a notification. Unsigned unless SIGN_APP_ID/SIGN_PKG_ID/NOTARY_PROFILE env provided (needs paid Apple Developer account).
- 2026-11-10 ADR-5: Renamed product to Avro Next (display name, bundle id org.avronext.inputmethod.AvroNext, executable AvroNext, app bundle 'Avro Next.app'). Supersedes the iAvro Next naming in ADR-1..4. Old test installs must be removed and the input source re-added.
- 2026-11-10 ADR-6: Info.plist switched to iAvro's flat input-method layout (top-level TISIntendedLanguage=bn, tsInputMethodIconFileKey, no ComponentInputModeDict). With modes, the parent source had no language and was not enable/select-capable, so it never appeared in System Settings' Bengali list. Pkg made non-relocatable (stray copies were being "upgraded" instead of /Library); build/pkgroot copies are unregistered from LaunchServices. Open question: macOS 27 picker may hide ad-hoc-signed input methods (iAvro has Developer ID; TIS properties otherwise identical).
- 2026-11-10 ADR-7: Test-signed with Apple Development cert (team 73Z8RM6PX9). After install, TIS reports Avro Next enabled+selectable+selected, it is in AppleSelectedInputSources and the process runs from /Library/Input Methods. Ad-hoc build never reached that state. Picker visibility and live typing still to be confirmed by user. Dev helper: Tools/tis_check.swift.
- 2026-11-10 ADR-8: Learning bug fixed. Cause: AvroController trusted IMKCandidates.candidateSelectionChanged, which reports a reset to row 1 when the panel reloads; that overwrote the learned default and riti then saved the wrong word (seen on disk: valobasi -> ভালবাসি). Fix: CandidateState is the single source of truth; arrows/page keys handled in handle(); the panel only mirrors the highlight; candidateSelectionChanged ignored; a mouse click still commits via candidateSelected. Regression test replays type/Down/commit/type/commit.
- 2026-11-10 ADR-9: Replaced IMKCandidates with own CandidateWindow (non-activating NSPanel, numbered cells, click commits). IMKCandidates captured arrow keys while visible and reset its highlight on reload; two workarounds failed. Grid style dropped (old saved value falls back to row).
- 2026-11-10 ADR-10: Git repo initialised (branch main). riti is a git submodule pinned at e1fd5a8 (recursive: khipro-classic). Project licensed MPL-2.0 to match riti. README covers install, keys, settings, build/sign. Not yet pushed: gh CLI not logged in.
- 2026-11-10 ADR-11: Releases published by GitHub Actions (.github/workflows/release.yml, macos-15) on v* tags using the built-in GITHUB_TOKEN; unsigned builds go out as pre-releases; Developer ID + notarization via repo secrets. Local push still needs the owner's GitHub auth (no credentials on this Mac; agent may not probe SSH).
- 2026-11-10 ADR-12: In-app updates. UpdateCore (testable, Foundation+CryptoKit) reads releases.atom + per-release update.json (avoids the 60/h unauthenticated API limit, which this network had already hit). UpdateManager: daily check, UNUserNotification + input-menu item, download to ~/Downloads, SHA-256+size verify, hdiutil mount, open pkg; Developer ID builds also require pkg signed by the same team. Workflow writes update.json and enforces tag==Info.plist version.
